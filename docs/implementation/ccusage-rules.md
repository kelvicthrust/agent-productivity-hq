# How ccusage counts, and where this app does the same

ccusage is the **oracle** for G5_3: three sessions per provider must match `ccusage <provider> session --json --offline` to the
token. It is never a dependency. This page records the rules the oracle applies, so the importers can follow them on purpose
instead of by guess.

## Where this comes from, and what it is not

These rules record the oracle implementation examined during importer development. Synthetic
fixtures exercise replay, deduplication, compaction, advisor usage and per-session attribution.
Source function names below identify the historical oracle implementation, not a dependency
installed by this application. See the [reconciliation guide](reconcile.md) to compare a new
installation against an independently obtained ccusage report.

Real owner-run reports, account details and session-specific measurements are excluded from the
public source. Synthetic regression success does not establish parity for every provider version
or for an installation's private history. The unsupported sidechain case below remains a limit.

## What this app does differently on purpose

- **Storage is by event, not by report.** Each event keeps its own session. ccusage's per-session report and this app agree when
  the same events are counted for the same session, which is what the rules above make true.
- **Sidechain** is read here from the line's `isSidechain` or from a transcript below `subagents/`, and a stored event only from
  its file's place (the database keeps no line flag); the oracle reads the line only. A main-thread transcript that holds
  sidechain-flagged lines is the one place the two can disagree on which copy survives (see `docs/implementation/reconcile.md`,
  "What a difference can still be").
- **Cache-write tokens of Codex** are kept in the `cache_write_tokens` column as a part of `input` (never added to the total) so the
  reconcile tool can compare them as their own category, as the oracle reports them.
- **A counter reset** (a total that goes down) is not taken whole as `data-and-sources.md` says (`ref = ZERO`): the oracle counts
  `last_token_usage`, or a saturating difference without it, and the importer follows it. Real-history reset coverage is not established by the public fixtures.
- **No usage is ever re-added from other fields:** Codex events carry the provider total (X3) and Claude's four categories add.
