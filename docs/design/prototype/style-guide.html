Kelvin Agent Crew: design system

The viewing and usage surface for the visual identity. It isn't a separate theme. Every swatch, specimen and component below renders from the same tokens.css, app.css and ui.js the prototype uses. Colour values and contrast ratios are read from those variables in your browser.

Status: draft for owner review Revision D4 (repair pass on D3; D3 built on D2 of 2026-11-05) D8 adds Paseo’s two status words, under Components › Status Canonical values: design-system/DESIGN.md Preview mirror: tokens.css Brief: DESIGN.md · Research: docs/archive/design/research.md
The owner approved the D2 playful-minimal direction in Review (r6), and D3 applied the owner's follow-up decisions (opens on This week, named Kelvin Agent Crew, system rounded font, light theme only). D4 is a usability and responsive repair in answer to an independent critique: it changes layout, navigation and wording, not colour, type or shape values. New or changed here: the phone tab bar, the provider ledger, the coverage strip, session identity, and local-scroll cues. Nothing in D4 has been verified in a rendered browser (the design session had none). Components are plain HTML/CSS specimens, not Astryx; library behaviour and Tailwind mapping still need verifying in Tech Spec (see Implementation mapping). Contrast figures are computed here, not an accessibility audit.

Identity

A cozy logbook for your agents: warm, a little cheeky, honest about gaps. Kelvin reviews what merged, where his agents spent their tokens, and which sessions link to that work. The familiar dashboard skeleton stays (filters, KPIs, aligned charts, tables). Personality comes from a warm cream canvas, rounder shapes, soft tactile depth, a grape action colour, and a tiny crew of agent "buddies" that stand in for sessions. Delight is saved for rare moments: first launch, a quiet day, recovery. It is still not a scoreboard: no productivity score, no streaks, no green/red deltas.

Kelvin Agent Crewproduct name chosen by the owner (Review r6)

The mark is three rounded bars in the delivery, Codex and Claude Code colours. The tallest bar has buddy eyes, a nod to the agent crew. The name was chosen after the mark; the mark itself is unchanged and hasn't been reviewed as a final logo.

Color

Warm neutrals carry the structure. Grape is the single action colour. Berry, teal and terracotta are data series and appear on marks only, never body text. Sunshine is an illustration accent only. Every provider and attribution signal pairs colour with shape, pattern or words.

Permitted pairings

ForegroundBackgroundUseRatio

Ratios use the WCAG 2.x relative-luminance formula on the token values loaded in this page. Text needs ≥ 4.5:1; UI component edges and chart marks need ≥ 3:1.

Typography

One shipped font file and two system stacks. A rounded display stack (self-hosted Nunito → ui-rounded → SF Pro Rounded → system sans) gives headings and big numbers a softer voice, and is used for display roles only. Body, labels and data use the system sans with tabular numerals. Sentence case, and units always follow numbers.

Decided by the owner (D9, 2026-11-18; supersedes Review r6's “no font files”): Nunito is self-hosted. One variable-weight latin woff2 ships with the dashboard, so nothing is fetched from a font CDN. If it fails to load, ui-rounded resolves in Safari on Apple platforms and other browsers show the system sans. Characters outside the latin subset fall back too, so design nothing that depends on exact glyph widths.

Layout & spacing

Medium density on a 4px base, unchanged from D1. Desktop uses a 12-column grid with 16px gaps and a 24px page gutter, up to 1440px wide. The filter bar is now a floating rounded panel on the canvas, and the nav uses pill items with no hard dividers.

Shape & depth

Rounder than D1. Depth comes from soft, offset, warm shadows; there are no hard block shadows and no glass. Buttons get a 2px darker bottom edge and press in by 3% when clicked, so they feel tactile without turning into costume.

Agent buddies

Small authored characters that stand in for agent sessions. The idea (each agent gets a character) is adapted from the owner's Pixel Agents reference. The drawing is our own minimal geometry, not pixel art and not copied assets. Shape still encodes provider: Codex is a rounded square with an antenna, Claude Code is a circle, and an unknown relationship is a dashed outline. Buddies are decorative (aria-hidden) and always sit beside text that says the same thing.

Where they appear: provider tags, Usage tree rows (root sessions large, children small), crew rows in the Root sessions and Child agents KPIs (one buddy per session, up to 9, then "+N"), setup discovery, and the quiet / empty / first-run illustrations. Never inside charts, and never as a score.

Session identity D4

A session row should be recognisable at a glance. It leads with the recorded agent name when the source has one (in this fixture only Paseo records carry a name). With no recorded name it leads with the recorded relationship ("Root session", "Native subagent", "Unknown relationship") and says "No name recorded". The technical ID stays visible but secondary, with a screen-reader prefix. Provider, relationship and PR association labels are all kept.

KPI cards

Merged PRs leads, on a berry-tinted surface (no coloured side rule). Session KPIs show a crew row. Comparisons are neutral text. Missing coverage replaces the value with words, never a zero.

Provider ledger in the tokens KPI, by card width D4

The card decides from its own inner width: two providers side by side need about 190px, so a card with less than 200px of inner width stacks them one per row, label left and value right. On a phone the whole card spans the row (the top-left frame). Provider totals are never combined, in any layout.

Provider token ledger (Usage page) D4

Labels may wrap; numbers never do. Included subsets sit under their parent with an elbow connector and a note ("included in input"), so they read as part of the total above and are never added again. At 1023px and below the two ledgers stack full width.

Coverage strip, by container width D4

Below 900px of container width the strip is compact source groups (a label column and one line per source); it only becomes the one-line capsule at 900px and wider, because a wrapped pill turns into an oversized oval. The strip carries status only. One prose explanation of a failure, with its freshness, coverage limit and recovery action, lives in the banner below.

Navigation & containment D4

A critique of D2 at 390px found labels spilling out of cards, clipped navigation and sideways page scrolling. D4's rules prevent those by construction, and a small review tool in the prototype lets anyone check the result.

WidthNavigationNotes
≥ 1024pxSide nav, "Sources & repos" set apart at the bottomUnchanged from D3
720–1023pxPill row under the app barAll five items fit without scrolling
< 720pxFixed bottom tab bar: icon over a 12px label, five equal tabs, 52px tall; current tab on the selection tint; issue count as a small badge on Sources"Sources & repos" shows as "Sources" but keeps its full accessible name. The page and the sticky filter summary no longer share the top with a nav row

Containment rules

  • Grid and flex children get min-width: 0 so long content can't force the page wider.
  • white-space: nowrap only for short labels and numbers that must not split, and never inside a card narrower than they are.
  • Components that must fit different widths adapt to their own width (container queries) with the safe layout as the default.
  • Sideways scrolling is allowed only inside a local scroller, and it shows an edge shadow plus a words-hint when it matters (year grid, wide tables).
  • Charts have a 240px minimum, because a 320px window leaves a 256px card body.

Avoid

  • Hiding a label with display: none when it is the only accessible name; use a visually-hidden style.
  • A pill radius on anything that wraps to several lines.
  • colspan in tables whose columns are hidden on a phone; give every row the same cells.
  • Repeating one failure explanation in the strip, a notice, a card and a banner.
  • Claiming a layout is contained without measuring it at 390px and 320px.

A year of merges

One cell per day for the last 12 months, Monday-start weeks. The berry ramp has 4 steps; the sunken cell is a covered zero (delivery history covers the whole lookback for tracked repos). Days in the selected period are outlined. Clicking a day opens it in Trends. Each cell has a text title, and the figure has a text summary (total, days with a merge, busiest day). There are deliberately no streaks or scores. It shows merges only, because local usage history doesn't cover the year.

Motion

From Emil Kowalski's animate skill (snapshot c8a7962): no motion on anything triggered by keyboard or done a hundred times a day; transform and opacity only; strong ease-out curves; under 300ms for UI; and entrances that play once, never on re-render. Delight motion is spent only on rare moments.

Voice & content

Friendly and plain, like a teammate's note, but every claim is literal. Warmth goes into greetings, quiet days and empty states. Numbers, labels and errors stay precise.

Say

  • "Morning, Kelvin": a greeting, with no judgement attached
  • "Here's what merged and where your agents spent their tokens"
  • "A quiet one. No recorded agent activity and no merges… a true zero, not missing data."
  • "Let's find your agents" (setup)
  • "History unavailable before [date]", "Linked sessions", "Suggested", "Owner-confirmed"

Avoid

  • "Great job!", "You're on fire", streaks, levels, badges for output
  • "Agent-produced PR", "hours saved", "more productive", "productivity score"
  • A cross-provider "Total tokens", or any cost / "$"
  • Jokes in errors or anything about lost data
  • Emoji as icons

Do's and don'ts

Do

  • Spend personality on rare moments and precise details, not on every card.
  • Keep buddies beside text, with shape matching provider.
  • State coverage in words beside any number that might be incomplete.
  • Keep Codex and Claude Code totals side by side.
  • Lead a session row with its recorded name or relationship; keep the ID secondary but present.
  • Put the primary action on the right.

Don't

  • Turn activity into a game score, streak or leaderboard.
  • Put buddies inside charts or animate data.
  • Add kicker labels above headings, coloured side rules, gradient text or hard block shadows.
  • Invent a name for a session that has none, or lead with a technical ID when a name exists.
  • Sum account and local usage, or filter account usage by repo.
  • Add a machine picker, folder picker, API-key field or password form.
